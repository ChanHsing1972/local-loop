# 设计日志

本日志记录关键工程决策及其证据，便于复盘和面试答辩；不记录任何 API 密钥或认证信息。

## 2026 年 8 月 27 日：核心闭环

- 建立 Provider、AgentEngine、LocalTools、ContextManager 与 SessionStore 的解耦结构，模型客户端仅负责传输。
- 使用原生函数调用及调用编号关联结果，不从普通文本中猜测工具 JSON。
- 首版提供目录、读取、搜索、写入和命令五个工具，并加入工作区路径校验、敏感文件阻止、SHA-256 陈旧写入保护、无 Shell 命令、环境净化、超时和输出上限。
- FakeProvider 驱动模型/工具循环测试，真实子进程集成测试在临时 Git 仓库中完成“读取缺陷、修改代码、运行 pytest、返回总结”的完整链路。

## 2026 年 8 月 27 日：持续交互界面

- 默认入口升级为基于 prompt-toolkit 与 Rich 的持续交互式 CLI，同时保留适合脚本和演示的 `run` 模式。
- 后续输入追加到同一消息历史；`/new`、`/resume`、`/sessions`、`/models`、`/model` 与 `/approval` 明确控制会话和运行策略。
- 终端界面与项目说明统一使用中文；面试要求的一分钟英文介绍作为必要例外单独保存。

## 2026 年 8 月 27 日：真实网关兼容与恢复

- 真实网关曾在工具结果回填后返回字符串或空响应，因此 Provider 增加标准对象、字典、JSON 字符串和纯文本的受控解析，并对空响应进行最多三次指数退避重试；业务错误仍立即显式失败。
- `urllib` 在当前 Python 环境访问模型列表时发生 TLS 握手超时，而 HTTPX 可正常连接，因此模型探测改用与模型客户端一致的 HTTPX，并为网络错误、429 与 5xx 增加有界重试。
- 部分思考模型拒绝强制 `tool_choice`，但能在 `auto` 模式下稳定发起原生调用，因此 `doctor` 采用真实运行参数，并通过两次请求验证“工具调用→结果回填→最终文本”的完整协议。
- 会话日志写入后同步落盘；恢复时忽略最后一条未写完事件，并为尾部缺失的工具结果追加状态未知错误，优先保证事实诚实和消息协议有效。
- 本地状态也纳入路径边界：`.localloop` 不得通过符号链接指向工作区外部，会话目录与历史文件使用仅当前用户可访问的权限。

## 当前主动接受的边界

- 安全控制用于减少误操作，不是操作系统沙箱；自动批准只用于可信、可恢复的临时工作区。
- 当前仅处理 UTF-8 文本，写入采用完整文件原子替换；尚未实现面向超大文件的补丁协议。
- 上下文预算使用可解释的字符近似而非特定模型 tokenizer；旧交互采用确定性状态、长度和短预览压缩，磁盘日志仍保留完整事件。
- 每个 Agent 轮次仍受模型调用次数和总时长限制；写入采用完整文件替换，尚未实现补丁协议。

## 2026 年 8 月 28 日：流式输出、可观察过程与配置修复

- 找到“回答慢”的主要感知原因：旧 Provider 等完整响应后才打印；同时空响应最多四次请求会叠加每次超时与 1/2/4 秒退避。正常 Agent 请求改为 SSE 流式传输，最多三次请求，并把重试原因显示到终端。
- Provider 按流式工具调用的 `index` 重组 id、函数名和分片 JSON 参数；正文边显示边累积，最终仍形成完整 Assistant 历史。已收到任何有效分片后若断流则不自动重试，防止重复输出或潜在副作用。
- 将空字符串、空 `choices`、缺失 message、同时缺少文本和工具调用统一分类为可重试空响应；认证、权限和无效请求仍立即失败。
- 用“模型正在分析什么、读取的文件与行号、搜索词、写入字节、实际命令、退出码和输出摘要”替代笼统的 `步骤 1/20` 展示。
- 修复 `.env` 只存在但不会被程序读取的问题：现在读取启动目录的 `.env`，显式环境变量优先；不自动读取 `-C` 目标仓库配置，避免信任陌生项目。
- 真实网关通过模型列表、原生工具调用和 Tool 回填诊断；真实临时项目端到端运行 6 次模型调用，完成两次写入并使 9 项测试通过。

## 2026 年 8 月 28 日：命令发现与发布身份

- 用带元信息的 `SlashCommandCompleter` 取代普通单词补全；输入 `/` 会自动展开全部命令与说明，前缀即时过滤，可用键盘选择和补全。帮助表与补全菜单复用同一份命令定义。
- 按项目所有者要求，发布检查不再强制匿名账号，而是验证公开仓库，并要求所有历史提交的 Author 和 Committer 统一为指定真实身份。
