# 从零读懂 LocalLoop

## 1. 先用一句话理解它

LocalLoop 是一个自己掌握控制循环的编程智能体：模型提出文本或工具调用，LocalLoop 验证并在本机工作区执行工具，把真实结果按协议交还模型，直到模型给出最终答案或程序触发明确的终止条件。

模型不是程序的控制器。它不能直接访问文件系统，也不能直接执行命令；它只能从五个工具的 JSON Schema 中选择动作。真正决定“是否执行、如何执行、怎样记录、何时停止”的是本地 Python 代码。

## 2. 最小运行链路

```text
用户输入任务
  -> InteractiveShell 创建/继续会话
  -> AgentEngine 准备上下文并请求模型
  -> Provider 解析正文或 tool_calls
  -> LocalTools 校验参数、审批并本地执行
  -> ToolResult 以相同 tool_call_id 回填
  -> AgentEngine 再次请求模型
  -> 模型输出最终文本，或程序按边界停止
```

整个项目最重要的不变量是：每个 Assistant 工具调用都必须对应一个具有相同 `tool_call_id` 的 Tool 结果。工具执行失败也要返回结构化失败结果，不能悄悄丢弃，否则下一次模型请求的消息协议会被破坏。

## 3. 建议的源码阅读顺序

### 第一步：`types.py`

先认识项目在各层之间传递的数据：

- `AgentConfig`：运行参数，API 密钥被排除在对象表示之外。
- `ToolCall`：模型给出的调用编号、工具名和 JSON 参数字符串。
- `AssistantTurn`：一次模型响应的完整正文、工具调用、停止原因和用量。
- `ToolResult`：本地执行结果，转换为 OpenAI 工具消息时保留调用编号。
- `RunResult` 与 `RunStatus`：一轮 Agent 运行的终局状态。

### 第二步：`agent.py`

从 `AgentEngine.run` 阅读主循环。每次循环依次完成：检查总时长、显示简短等待状态、压缩上下文、请求模型、持久化 Assistant 消息、执行全部工具调用、持久化 Tool 结果、判断是否继续。成功不是“工具返回 0”，而是模型在没有新工具调用时返回非空最终文本。

主循环有六类保护性终止：总时长耗尽、模型调用次数耗尽、连续三次相同工具调用、上下文预算失败、Provider 错误、用户中断。模型输出因长度限制被截断也会明确失败，避免把半段答案误报为完成。

### 第三步：`tools.py`

`LocalTools` 提供五个本地能力：

| 工具 | 输入 | 关键约束 |
| --- | --- | --- |
| `list_files` | 相对目录、深度 | 忽略 Git、会话、缓存和敏感配置 |
| `read_file` | 相对路径、行号 | UTF-8、最多 400 行、最多 1 MiB、返回 SHA-256 |
| `search_text` | 字面文本、目录、glob | 优先 `rg`，没有 `rg` 时用 Python 搜索 |
| `write_file` | 路径、完整正文、旧哈希 | 现有文件必须读后写；展示 diff；临时文件 + `os.replace` |
| `run_command` | argv 数组、cwd、超时 | 不启用 Shell；净化环境；限制 120 秒和输出体积 |

所有路径必须相对工作区，绝对路径、`..`、越界符号链接、`.env`、Git 内部目录和常见凭据文件会被拒绝。写文件与运行命令默认需要用户批准。`run_command` 的数组直接交给 `subprocess.run`，因此分号、管道和重定向不会被 Shell 再解释。

### 第四步：`provider.py`

Provider 只处理模型接口传输和响应解析，不决定 Agent 下一步。普通响应由 `_parse_response` 解析；流式响应由 `_parse_stream` 逐片处理。正文分片一边显示，一边拼成完整历史；工具调用可能把 id、函数名和参数拆到多个 chunk 中，因此按 `index` 累积，流结束后再形成 `ToolCall`。

认证、权限和无效请求立即失败；连接、超时、限流、服务端错误和语义空响应进行有限重试。若正文已经显示后发生断流，则不自动重试，因为已显示内容无法可靠撤回，重试还可能造成重复文字或重复副作用。

### 第五步：`session.py` 与 `context.py`

会话采用仅追加 JSONL。第一条是元数据，之后保存系统、用户、Assistant、Tool、用量、运行时变更和终局事件。每次追加都会 flush 和 `fsync`，文件权限为 `0600`，目录权限为 `0700`。恢复时只容忍最后一条未写完的 JSON；若崩溃发生在 Assistant 工具调用之后、Tool 结果之前，程序追加“执行状态未知”的失败结果，而不是猜测动作是否完成。

上下文预算使用字符数近似。前两条系统提示和原始任务固定保留；较早消息被确定性压缩；最近工具交互完整保留。Assistant 调用与其 Tool 结果始终作为一组处理，以免生成不合法的历史。

### 第六步：`interactive.py` 与 `cli.py`

`InteractiveShell` 负责持续输入、Rich 渲染、底部状态栏和斜杠命令。空闲时动态补全条件关闭，不会为菜单预留终端空间；只有首字符输入 `/` 后，补全状态才申请菜单空间并展开命令，可按前缀过滤、上下键选择、Tab 补全、Enter 执行。`/resume ID` 会恢复模型上下文，并重绘已保存的用户与助手消息；系统提示和体积较大的 Tool 结果不会直接铺满窗口。`/delete ID` 在确认后删除单个会话；删除当前会话会同时清空内存上下文，下一条普通输入创建新会话。

`cli.py` 提供三种入口：默认或 `chat` 启动交互模式；`run` 执行一轮非交互任务；`doctor` 检查配置、模型列表、原生工具调用和 Tool 结果回填。`doctor` 是真实网关协议检查，不等同于完整编程任务成功。

## 4. 一次消息在程序中的形状

假设模型要读取 `app.py`，历史会依次出现：

```json
{"role":"assistant","content":null,"tool_calls":[{"id":"call_1","type":"function","function":{"name":"read_file","arguments":"{\"path\":\"app.py\"}"}}]}
{"role":"tool","tool_call_id":"call_1","name":"read_file","content":"{\"ok\":true,...}"}
```

Agent 不从自然语言中猜测动作。它只执行 `tool_calls`；工具正文是 JSON 字符串，成功和失败都可以交给模型继续判断。

## 5. 交互命令

| 命令 | 作用 |
| --- | --- |
| `/help` | 显示全部命令 |
| `/status` | 显示当前模型、工作区、审批和会话 |
| `/new` | 放下当前上下文，下一条输入创建新会话 |
| `/resume ID` | 恢复指定 JSONL 会话并重绘历史对话 |
| `/sessions` | 列出最近十个会话 |
| `/delete ID` | 确认后删除指定会话 |
| `/models` | 查询网关模型列表 |
| `/model ID` | 切换当前进程使用的模型 |
| `/approval ask|auto` | 切换逐次确认或自动批准 |
| `/clear` | 清屏并重画启动信息 |
| `/exit`、`/quit` | 退出程序 |

`/new` 只切换当前上下文，不删除磁盘记录；`/delete ID` 才会删除历史会话文件。prompt-toolkit 的输入历史文件与模型会话是两种数据：前者用于上下键找回曾输入的文本，后者保存完整模型/工具协议。

## 6. 安全边界与诚实表述

LocalLoop 的保护是防误操作层，不是操作系统沙箱。路径限制、敏感文件阻止、无 Shell argv、审批、环境净化、超时和命令黑名单能降低常见风险，但获准运行的 Python、编译器或其它程序仍继承当前用户权限。自动批准只能在可信、可恢复、最好是临时复制的工作区使用。

SHA-256 是乐观并发控制：模型读取文件后，若文件被别人改过，旧哈希写入会失败。它防止静默覆盖，并不替代 Git。原子替换避免半文件，但完整文件写入不适合超大文件。

## 7. 测试怎样分层

- 单元测试：覆盖配置、协议解析、上下文压缩、会话恢复、工具边界、交互命令和失败分支。
- 本地集成测试：在临时 Git 仓库中用脚本化 Provider 真实读写文件并运行 pytest，验证模型之外的闭环。
- 真实协议测试：`localloop doctor` 对真实网关发请求，验证模型列表、原生调用与结果回填。
- 真实任务演示：在 `scripts/prepare_demo.py` 生成的临时价格项目中，让真实模型读、改、测并总结；这是对用户体验和模型行为的验证，不能由单元测试代替。

## 8. 已知限制

项目只处理不超过 1 MiB 的 UTF-8 文本；读取单次最多 400 行；写入是完整文件替换；上下文预算不是精确 tokenizer；没有容器或操作系统沙箱；命令黑名单不可能穷举所有间接破坏方式；模型输出质量与延迟仍受网关和模型影响；进程崩溃后的工具执行只能标记为状态未知，无法承诺 exactly-once。
