# 设计答辩准备

## 一句话架构

LocalLoop 是一个有边界的状态机：模型提出带类型的函数调用，程序在本地验证并执行，把匹配调用编号的结果追加到历史中，再由模型根据真实结果决定下一步。

## 需要能够回答的问题

### 为什么使用原生工具调用，而不是让模型在普通文本中输出 JSON？

原生工具调用提供明确的调用编号、工具名称和参数边界，可以可靠关联多个调用及其结果，避免解析 Markdown 或从普通文本中猜测 JSON。`doctor` 会直接拒绝不支持原生函数调用的模型，而不是静默使用脆弱的降级方案。

### 为什么使用 OpenAI Python 客户端仍然符合题目要求？

客户端只承担兼容接口的请求与响应传输，不管理对话、不选择或执行工具、不存储文件、不压缩上下文、不控制重试流程，也不决定何时终止；这些关键责任全部由本仓库自行实现。

### 为什么命令使用 argv 数组，而不是 Shell 字符串？

argv 直接交给 `subprocess`，并明确设置 `shell=False`。Shell 元字符因此只是普通参数，而不会成为额外语法。这降低了命令注入风险，也让待批准的命令更准确。代价是不能直接使用管道和重定向。

### SHA-256 写入保护解决什么问题？

`read_file` 会计算整个文件的哈希。更新现有文件必须带回这个哈希；如果其他进程在读取后修改了文件，写入会被拒绝，模型必须重新读取，从而避免静默覆盖较新的内容。

### 上下文压缩为什么仍然满足消息协议？

程序会把 Assistant 工具调用消息与其后所有工具结果视为一个不可拆分的交互组。旧的完整交互组会被替换成普通 Assistant 摘要，最近交互保持原样，因此不会留下缺少结果的工具调用。如果最近上下文本身仍然超出预算，程序会明确停止，而不是发送不完整历史。

### 为什么不使用模型生成摘要？

确定性压缩不增加 API 调用、不会编造事实、容易测试，而且磁盘上的 JSONL 仍保存完整历史。代价是很久以前的语义细节可能丢失，这也是当前实现主动接受的边界。

### 交互式 CLI 如何保持多轮上下文？

第一次普通输入会创建会话并写入系统消息和用户任务；一轮完成后，最终 Assistant 消息和全部工具结果仍保留在内存与 JSONL 中。下一次普通输入作为新的 User 消息追加到同一历史，再启动一个新的有界 Agent 轮次。`/new` 才会丢弃当前内存上下文，`/resume` 可以从 JSONL 恢复。

### 循环在什么情况下停止？

每轮会在模型返回非空最终文本、达到最大步骤、达到总时间、连续三次重复同一调用批次、返回空输出、接口失败、上下文耗尽或用户中断时停止。交互式外壳在一轮停止后仍然存活，允许继续提问或开始新会话。

### 哪些安全能力已经实现，哪些没有？

文件路径不能越过工作区，敏感路径被阻止，更新需要当前哈希，写入和命令默认需要批准，子进程使用无密钥环境、无 Shell、超时和输出上限。这些机制用于降低误操作风险，不是内核级沙箱；用户批准的任意可执行程序仍可能产生当前账户权限允许的副作用。

### 如果再增加一周时间，会做什么？

优先增加容器或操作系统沙箱、流式模型输出、面向大文件的补丁编辑、精确 tokenizer、属性测试，以及包含任务成功率和工具效率指标的评测集，而不是继续增加表面功能。
