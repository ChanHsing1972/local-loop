# 两分钟演示视频脚本

## 1. 视频只证明四件事

1. Agent 能在真实模型驱动下完成一个包含阅读、修改和测试的编程任务。
2. 模型正文流式显示，本地动作展示具体对象和结果，而非只有抽象进度。
3. 模型不能直接操作电脑；核心循环、工具、历史、错误和终止由 LocalLoop 实现。
4. 项目清楚区分防误操作机制与操作系统沙箱。

安装和 `doctor` 放在录制前完成，不要浪费成片时间滚动依赖日志或模型列表。

## 2. 录制前准备

1. 创建干净虚拟环境并安装当前检出，确认 `localloop --version` 正确。
2. 在画面外运行 `localloop doctor`，验证真实模型原生工具协议。
3. 在仓库执行 `python scripts/prepare_demo.py`，记住输出的临时目录。
4. 进入临时目录运行 `pytest -q`，确认演示项目初始失败；不要修改仓库内的夹具。
5. 终端宽度建议 100-110 列，字号保证 1080p 画面可读；关闭通知、隐藏私人路径和任何凭据。
6. 清屏，准备好固定任务文本，并保留一次已跑通的备用录制。

固定任务：

```text
保持公共 API 不变。找出并修复金额精度问题和折扣阈值的边界 Bug，补充边界测试，并运行全部测试。
```

## 3. 120 秒时间线

### 0-10 秒：先展示真实问题

画面显示初始 pytest 失败摘要。旁白：“这是一个有金额精度和阈值边界缺陷的小项目。接下来我让 LocalLoop 自主读取、修复并验证。它没有使用 Agent 框架，控制循环和本地工具由我自己实现。”

### 10-22 秒：启动与交互界面

运行 `localloop --auto-approve`。输入 `/`，快速展示命令和中文说明，再按 Esc 或清空输入，粘贴固定任务。此处应能看出：输入 `/` 前界面没有菜单空白，输入后才出现菜单。

旁白：“斜杠菜单只在需要时出现，支持筛选和键盘操作。演示使用可丢弃临时目录，所以开启自动批准；真实项目默认逐次确认。”

### 22-72 秒：保留完整因果链

画面按真实顺序保留：列文件；读取 README、源码和测试；模型正文流式出现；展示源码 diff；展示新增或修改的边界测试 diff；运行 pytest；展示退出码与多行测试摘要；模型根据结果给出最终总结。纯等待可加速，动作顺序不可重排。

旁白：“终端把模型等待压缩成一行，主要展示真实事实：读了哪个文件和行号、写入哪个文件、待执行命令、退出码和测试输出。Provider 逐片显示正文，并在本地重组可能被拆开的工具参数。”

### 72-88 秒：连续会话与删除历史

在同一会话输入：“用两句话解释修复依据，并说明一个安全限制。”展示回答能引用上一轮结果。随后输入 `/sessions`，指出 `/resume ID` 可以恢复、`/delete ID` 会确认后删除，但不要在主演示中删除刚完成的记录。

旁白：“普通输入会继续当前历史；`/new` 开始新上下文但保留日志，`/resume` 恢复，`/delete` 才删除指定记录。”

### 88-108 秒：快速讲清代码结构

切换编辑器，按顺序停留：`agent.py` 主循环与终止；`provider.py` 流解析；`tools.py` 路径、哈希、审批和 `subprocess.run`；`context.py` 完整工具组压缩；`session.py` JSONL 恢复。

旁白：“Agent 编排状态，Provider 只传输和解析，Tools 本地验证执行，Context 控制上下文，Session 保存可恢复历史。模型提出动作，但程序掌握权限和终止。”

### 108-118 秒：证据与边界

显示最终 pytest 行和项目测试总览截图或终端摘要。旁白：“自动化测试覆盖协议、异常恢复和安全边界；真实 API 负责验证模型协议和任务效果。这些保护能减少误操作，但不是操作系统沙箱。”

### 118-120 秒：结束

字幕：“LocalLoop - control, evidence, recovery.” 保留短暂结束缓冲，不再引入新概念。

## 4. 剪辑与可信度

- 可以 2-4 倍加速纯等待，但不要剪掉“读 -> 推理依据 -> diff -> 测试 -> 根据结果总结”。
- 至少保留一小段连续出现的模型正文，以证明流式输出。
- 不要把两次不同运行拼成一次看似连续的成功链路。
- 不展示 `.env`，即使密钥已打码；也不展示 API 请求头、Shell 历史或无关通知。
- 如果真实模型失败，先停止录制并在画面外诊断；主成片使用完整、诚实的一次运行。

## 5. 导出验收

导出 H.264 MP4，建议 1080p，严格小于 120 秒和 200 MB。完整观看最终文件，确认开头问题、关键 diff、最终测试、架构说明和限制都清楚可见，且没有密钥或私人信息。
